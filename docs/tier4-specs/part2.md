## Conventions used by every spec below

- **Rules by number.** "AC-0/T4 #n" is a rule from tier4-technical §3 (27 to 39); "AC-0/T3 #n" from tier3-plan §3. Stated at the point they bite.
- **Standard seed field.** `SeedField` (K3), read with `parseBoundedInt(text, { min: 0, max: SEED_MAX })`, `SEED_MAX = 2^31 - 1`; refused with a message and the old seed kept. The seed is shown beside every seeded run (`Provenance seed=`), with "new seed".
- **Broken mode, fixed mode, counterexample (AC-0/T4 #29).** Every simulating lesson has a broken mode and a fixed mode, a **named safety rule**, and a counterexample object (lowest failing seed, shortest explorer path, or witness schedule). The builder searches seeds from **1** upward (`forSeeds({ from: 1, to: 201 }, ...)`), pins the lowest failing seed as `BROKEN_SEED` in the test **together with the violated rule index or message**, asserts the fixed mode passes the same seeds, asserts the broken mode fails on **at most 180 of 200 seeds** (90%) and prints "fails on k of 200 seeds" on screen. The lesson's default seed **in broken mode** is `BROKEN_SEED`. A seed-free hand-built schedule that also violates the rule is a second test. Each spec below gives a **target band** for the broken fraction (my scratch estimate); the builder tunes the one named knob until its measured fraction lands inside the band, then pins it.
- **What the screen says about a check (AC-0/T4 #27, #28).** Four fixed phrasings, produced by one pure helper in the lesson's `model.ts` from the check's result object, never typed: **Exhaustive** "holds in all N reachable states of this model (bounds)"; **Truncated** "no violation in the first N states explored; not exhaustive"; **Sampled** "held on k of k seeded schedules (seeds a to b); sampled, not exhaustive"; **Liveness** "no decision by T on k of 200 seeds" (always separate from safety). A bounded check never says "impossible", "always" or "can never" about the unbounded system; the theorem version is a `ClaimLabel kind="theorem"` ("argued, not run here", K4-8).
- **Kit timing.** B1 is **wave 1**: K4-1 (distSim v2) and K4-2 (`core/explore`) are **not** available to it (they are built during wave 1 and gate wave 2; tier4-plan §6.2 says B1 uses `distSim` as it stands). B4 is **wave 2** and uses K4-1, K4-2 (`explore`, `PureProtocol`, `networkExplorer`, `asDistNodes`, `TracePlayer`) and K4-8 (`ClaimLabel kind="theorem"`) exactly as tier4-technical §2.1 and §4.1 define them. - **Linking.** Rule 13: a lesson links by id only to lessons that exist or are earlier in its own batch or wave. Wave-1 soft links named in words only: `metastable-failures` does not link `backpressure`; `chaos-engineering` does not link `slos-error-budgets`. - **Colour vocabulary.** CLAUDE.md's table applies; plain categories (nodes, lanes, proposers) take `orange`/`amber`/`pink`/`sky`, never `--ok`/`--bad` as decoration. Each spec's **Watch** line maps colours to meanings; the lesson's `watch` text states them.
- **Try-this rule.** Each `tryThis` entry starts from the lesson's **default state** (stated in the spec) and the entries are written to be performed **in order**, each one naming the control it changes and **ending by resetting** if the next entry needs the default; the test `try-this N:` replays entry N headless from the default state and asserts the sentence's numbers (computed, never typed in the lesson text).

**`failure-detectors` · Failure Detectors & Heartbeats**
Track `arch` · *"You can't tell dead from slow, only guess well"* · Builds on: `timeouts-deadlines`, `health-checks`, `physical-clocks-skew`, `distributions` · **[domain review]**
**Fence.** `service-discovery-mesh` keyIdeas 1 and 2 teach registry TTL plus cache refresh and "a shorter TTL evicts live instances when heartbeats are lost"; `health-checks` teaches probe period times threshold; `timeouts-deadlines` teaches a timeout that frees the caller without cancelling the callee. **Starts where those stop:** this lesson asks what a monitor can ever know from silence, measures the false-suspicion against detection-time trade-off, makes the crash-versus-pause indistinguishability a computed artefact, and adds the two real designs (phi-accrual, SWIM indirect probes). Registry TTL, probe configuration and deadlines are not re-taught; scene 1 opens by saying "a TTL is a fixed timeout; here is why that is a guess".
**Spec.** Four scenes. Model for scenes 1 to 3: two nodes **M** (monitor) and **P** (peer) on `distSim`. P sends a heartbeat every **Δ = 100 ms** (`HEARTBEAT_MS`, a named constant, shown, not a control). Link delay is `LATENCY_MIN_MS + Exp(mean s)` with `LATENCY_MIN_MS = 1` and the **jitter slider** `s` (5 to 60 ms, step 5, default 20), implemented as `latency: (rnd) => 1 + exponential(rnd, 1 / s)` (K3-1), truncated at `LATENCY_CAP_MS = 300` so completeness has a bound (truncated mass at s = 40 is e^-7.5, about 0.06%; the closed forms below are stated for s <= 40 and the slider's last stops show a "closed form is approximate here" Hint; **uncertain, verify the cut-off against the test**). M suspects P when **T ms** have passed since the last heartbeat arrived; the next heartbeat un-suspects it, and each T-expiry while P is alive and not paused is one **false suspicion**.
- **Scene 1 · A timeout is a guess.** Controls: **timeout T** slider 120 to 600 ms step 10; **jitter** slider; **rule** `Segmented` (`fixed timeout` default; `phi accrual` once scene 3's rule exists, same control); buttons **Run 10 s**, **Crash P at 5 s**, **Pause P 5.0 to 5.6 s**, **Reset**; `SeedField` (default `BROKEN_SEED`). Output: a lane of heartbeat arrivals on a time axis (a tick per arrival), M's suspicion bars (`--bad` while P is alive, `--ok` after a real crash), counters (false suspicions, detection time after a crash), and a `Plot2D` of the **trade-off curve in closed form**: x = T, left y = false suspicions per minute `600 * 0.5 * exp(-(T - Δ) / s)` for T >= Δ, right y = mean detection time `T + (1 + s) - Δ/2`. Dots on the curve are measured over **200 seeded 60 s runs** (labelled **sampled**).
- **Scene 2 · Crash or pause?** Two runs, same seed: **A** crash P at 5.0 s; **B** pause P over [5.0, 5.0 + D) s, **D** slider 100 to 3000 ms step 100 (default 600). Side by side: M's observation list (arrival time of each heartbeat) for both, and a bar between them saying **"identical up to t = X ms"**, X = the first post-resume heartbeat's arrival (5,000 + D + its delay), read from the model. A **verdict game**: the learner moves a "decide at" slider and presses **Say crashed** or **Say paused**; the page evaluates the answer in both worlds and reports "right in one world, wrong in the other" for every decision time before X, and which world is right after X. **The wrong move and its refusal text (pinned):** answering "paused" at t < X gives "In run A the peer is dead. M's observations were the same until X ms, so this answer was a guess." Rule 27: "no detector can tell these two runs apart before X" is **exhaustive by construction** (equal observation lists, asserted by a test); "no detector achieves both completeness and accuracy in an asynchronous system" is a `ClaimLabel kind="theorem"` (argued, not run here; the scene is one instance, not the theorem).
- **Scene 3 · Phi accrual.** M keeps the last **W = 100** inter-arrival times and models them as normal with sample mean μ and standard deviation σ. It reports **φ(t) = -log10( P(next arrival later than t) )**, `P = 1 - Φ((t - μ) / σ)` (the model of the 2004 phi-accrual paper; **from memory, verify authors and year before naming them**; Cassandra and Akka are said to use variants, from memory). Control: **threshold φ** slider 1 to 16 (default 8). The φ(t) curve after the last arrival is drawn with the threshold line; the **implied timeout** `μ + σ * z`, `z = Φ^-1(1 - 10^-φ)`, is printed and moves when the jitter slider moves (a fixed T does not). A readout compares, over the 200-seed sweep, the **requested** per-check false-alarm probability `10^-φ` with the **measured** rate and says in words "φ is the model's statement, not a promise: real inter-arrival times are not normal" (see Correctness: the two are not asserted equal).
- **Scene 4 · SWIM, ask a friend.** Six nodes: M, B (the target) and four others H1 to H4, on `distSim` with the **global** `loss` slider **p** 0 to 40% step 5 (default 10%; every message lost independently with p) and **k indirect probes** slider 0 to 4 (default 0). Each protocol period M pings B; if no ack arrives in the period, M asks k random others to ping B (ping-req); if neither path acks, M **suspects** B (suspect-then-confirm and incarnation numbers are named only; the 2002 SWIM paper is **from memory, verify**). Toggle **cut M and B from each other**: symmetric `partition(M, B, ...)` between those two nodes only, so **M cannot reach B, everyone else can**, which needs no K4-1. With the cut on and p = 0: k = 0 suspects B every period; k >= 1 never does. *(Optional, only if K4-1 has merged before B1 is built: a one-way cut `partition(..., { oneWay: true })`. Otherwise omitted; nothing depends on it.)*
**Out of scope.** Registry TTL and refresh (`service-discovery-mesh`), probe configuration (`health-checks`), deadline propagation (`timeouts-deadlines`), consensus and leader election (`raft`; named), the FLP result (a later lesson, named in words, not linked: the theorem chip says "from the same family of results"), gossip dissemination (next lesson), detector classes beyond naming completeness and accuracy (Chandra and Toueg, 1996, from memory; named only if the author is certain).

**Model and oracles (every number from the model).**
- **Per-gap false suspicion.** Consecutive arrivals differ by `Δ + (d_k - d_{k-1})`, and `d_k - d_{k-1}` is Laplace with scale s, so `P(gap > T) = 0.5 * exp(-(T - Δ) / s)` for T >= Δ. Expected false suspicions in n gaps is `n * P` (linearity of expectation: exact although gaps are correlated). **Oracles:** 20,000 seeded gaps within 3 standard errors; and numerical integration of the difference density (trapezoid, 1e-6 step).
- **Mean detection time** after a crash at a uniform phase: `T + (1 + s) - Δ/2`. Oracle: 5,000 seeded crash times.
- **Phi.** `φ(t) = -log10(1 - Φ((t - μ)/σ))`; the tail below 1e-12 loses precision as `1 - Φ`, so compute `0.5 * erfc(z / sqrt(2))` and **clamp displayed φ at 16** ("16 or more"). Oracle: scipy `norm.sf` values typed into the test from vector 3 below, not from the lesson's output.
- **SWIM.** A direct probe fails with `q = 1 - (1 - p)^2`; one indirect path M-H-B-H-M succeeds with `(1 - p)^4`; with k independent helpers the **false-suspicion probability per period** is `q * (1 - (1 - p)^4)^k`. Oracle: **exhaustive enumeration of all 2^(2+4k) loss patterns** weighted by p (k <= 3, at most 16,384 patterns), plus 100,000 seeded periods within 3 standard errors.
**Test vectors (hand-worked and double-checked; scratch confirmed with scipy).**
1. *Per-gap rule.* Δ = 100, s = 20, T = 185: `0.5 * e^-4.25 = 0.5 * 0.014264 = 0.007132`; a 10 s run has 99 gaps, so expected false suspicions `99 * 0.007132 = 0.706`. T = 400: `0.5 * e^-15 = 1.53e-7`, times 99 = 1.5e-5 (zero on 200 seeds). T = 150: `0.5 * e^-2.5 = 0.04104` per gap, `600 * 0.04104 = 24.6` per minute.
2. *Detection time.* s = 20: T = 185 gives `185 + 21 - 50 = 156 ms`; T = 400 gives `400 + 21 - 50 = 371 ms`.
3. *Phi.* μ = 100, σ = 10: t = 110, z = 1, `P = 0.158655`, φ = 0.7995; t = 120, z = 2, P = 0.022750, φ = 1.6430; t = 130, z = 3, P = 0.0013499, φ = 2.8697 (`10^-2.8697 = 0.0013499`); t = 150, z = 5, P = 2.8665e-7, φ = 6.5426. **φ = 8** needs `P = 1e-8`, z = 5.6120, implied timeout `100 + 56.12 = 156.12 ms`; with σ = 30 it is `100 + 168.36 = 268.36 ms`. φ = 3 gives 130.90 (σ = 10) and 192.71 (σ = 30).
4. *SWIM.* p = 0.1: `q = 1 - 0.81 = 0.19`; indirect success `0.9^4 = 0.6561`, failure 0.3439. k = 0: 0.19. k = 1: `0.19 * 0.3439 = 0.065341`. k = 2: `0.19 * 0.3439^2 = 0.022471`. k = 3: `0.19 * 0.3439^3 = 0.0077277`. p = 0.2, k = 3: `0.36 * (1 - 0.4096)^3 = 0.36 * 0.20581 = 0.07409`.
5. *Indistinguishability.* Same seed, runs A and B: M's arrival lists are equal for every arrival time below `5,000 + D + 1` ms (the first post-resume heartbeat is sent at `5,000 + D` and cannot arrive sooner than the 1 ms minimum delay). Asserted for D in {100, 600, 3000} and 50 seeds.

**Quiz.**
- **Q1 (misconception: a timeout detects a failure).** M has heard nothing from P for 300 ms. What has M learned?
  - A. That P has crashed, because a live process always answers in time
  - B. Only that nothing arrived: P may be crashed, paused or just slow ✓
  - C. That the link is down, since a crashed node would have said so
  - D. That P is slow, because a crashed node closes its connection first
  - Distractors: A = silence means death; C = blames the link; D = assumes a crash announces itself.
- **Q2.** You raise the timeout from 185 ms to 400 ms. What changes in this model?
  - A. Both false suspicions and detection time fall together
  - B. Almost no false suspicions, and detection takes longer ✓
  - C. False suspicions rise, because a longer wait lets more delay in
  - D. Nothing, since the heartbeat interval alone sets detection time
  - Distractors: A = no trade-off; C = reversed; D = ignores the timeout.
- **Q3.** Why can a phi-accrual detector adapt where a fixed timeout cannot?
  - A. It sends heartbeats faster whenever the network looks busy
  - B. It asks other nodes to confirm every suspicion before acting
  - C. Its implied timeout moves with the jitter it has recently seen ✓
  - D. It measures the true crash time, so it never raises a false alarm
  - Distractors: A and B = other designs; D = promises certainty.
- **Q4.** M cannot reach B, but H can. What does a ping-req through H tell M?
  - A. Whether B is alive, over a path M's own cut does not touch ✓
  - B. Whether H is alive, because H forwards the probe to B
  - C. Nothing useful, because H shares the same cut with M
  - D. That B has crashed, because the direct ping already failed
  - Distractors: B = confuses helper and target; C = false shared fate; D = treats one failed path as proof.
- **Q5 (numbers).** With loss p = 0.1 on every message and one helper (k = 1), the false-suspicion chance per period is about:
  - A. 19%, exactly the same as with no helper at all
  - B. 6.5%: 0.19 times the chance the one helper path also fails ✓
  - C. 0.8%, which is what three helpers failing together would give
  - D. 34%, the chance the helper path fails by itself
  - Distractors: A = helper adds nothing; C = wrong k; D = forgets the direct probe must fail too.

**`paxos` · Paxos**
Track `arch` · *"Agree on one value even when proposers duel"* · Builds on: `raft`, `quorums`, `consistency-models` · **[domain review]**
**Fence (quoted).** `raft` keyIdeas: (1) "Randomised election timeouts mean one server usually times out first and wins cleanly." (2) "A leader needs a majority (3 of 5) of votes and of replicas to commit." (3) "Terms work like a logical clock: seeing a higher term makes any node step down." (4) "A minority partition can't commit anything, so no split-brain writes survive." `quorums` owns `R + W > N` for a register; `consistency-models` owns what a replicated log can promise. **What differs (the lesson opens by saying so):** Raft makes a *leader* a first-class role and checks safety through terms and log matching; Paxos separates **safety from who is proposing**: any number of proposers may try at once, each with its own **ballot number**, and safety holds whatever the schedule; only **liveness** needs a stable proposer. Owned here: ballots, the two phases, **duelling proposers**, why an accepted value can never change, and Multi-Paxos as "a stable proposer skips phase 1". Out of scope: election timeouts, log replication and terms (`raft`), `R + W > N` (`quorums`).
**Spec.** One protocol, **single-decree Paxos**: acceptors **a1, a2, a3**, proposers **P1** (wants value **A**, ballots 1, 3, 5, ...) and **P2** (wants **B**, ballots 2, 4, 6, ...). Messages: `Prepare(b)`; `Promise(b, accepted ballot, accepted value)`; `Accept(b, v)`; `Accepted(b, v)`. Acceptor rules: promise `b` only if `b >` its promised ballot; accept `(b, v)` only if `b >=` its promised ballot; every accept is recorded in a ghost **votes** list. Proposer rule: after `Promise`s from a **majority (2 of 3)**, propose the **value of the highest accepted ballot among them**, or its own value if none. A value is **chosen** when a majority of acceptors voted for the same `(ballot, value)`. The protocol is written once as a `PureProtocol` (nodes, `init`, `onMessage`, `onTimeout` for a proposer's retry) and used by every scene.
- **Scene 1 · Drive the scheduler.** The learner is the network. **Spec.** Rules (the lesson prints them; the algorithm is from the 2014 "logical physical clocks" paper of Kulkarni and colleagues, **from memory, verify the authors, year and the exact rule before naming them**). A node's timestamp is `(l, c)`: `l` a wall-clock reading, `c` a small counter. Let `pt` be the node's physical clock. **Local or send event:** `l' = max(l, pt)`; `c' = c + 1` if `l' = l`, else `0`. **Receive of `(l_m, c_m)`:** `l' = max(l, l_m, pt)`; then `c' = max(c, c_m) + 1` if `l' = l = l_m`; `c + 1` if `l' = l` only; `c_m + 1` if `l' = l_m` only; `0` if `l' = pt` alone. Timestamps compare **lexicographically** (`l` first, then `c`).

**Model and oracles.**

- **Closed form for the seeded fraction** (`e1, e2` independent uniform on `[-δ, δ]`; `D = e1 - e2` triangular on `[-2δ, 2δ]` with `P(D >= x) = (2δ - x)^2 / (8δ^2)` for `0 <= x <= 2δ`; `g` uniform on `[0, G]`): `P_break = (1/G) * ∫_0^G P(D >= w + g) dg`. **Oracle:** the integral by quadrature against 10,000 seeded races within 3 standard errors, **and** a brute-force grid over `(e1, e2, g)` for the deterministic verdict `s2 > s1` against the closed condition `w + g + e2 - e1 > 0` (a few hundred thousand cases, exact).

**Spec.** One model, `rigour(C, p0, tau, w)` (all **invented** constants, `Provenance invented`): **total expected cost** of deciding with `r` hours of rigour is `total(r) = w * r + p0 * C * exp(-r / tau)`, where `C` is the hours of work to **undo** the decision if it turns out wrong, `p0` the chance it is wrong with **no** rigour, `tau` how fast rigour reduces that chance (hours; `exp(-r/tau)` of the original risk remains), `w` the cost of one hour of rigour in hours of work (default 1). The optimum is `r* = tau * ln(p0 * C / (tau * w))` when `p0 * C > tau * w`, else **0** (decide now); and **`total(r*) = r* + tau * w`**. The **crossover cost** below which any deliberation costs more than it saves is `C* = tau * w / p0`.

**`hiring-interviewing` · Hiring & Technical Interviewing**
Track `lead` · *"A loop is a measuring instrument, and instruments have noise"* · Builds on: `mentoring-delegation`, `distributions` (soft links in words to `hypothesis-testing-ab`) · **[domain review]**: statistical validity claims, computed from the model with a stated toy
**Fence.** `mentoring-delegation` owns coaching and feedback (out of scope here); `hypothesis-testing-ab` and `distributions` own the statistics themselves (this lesson **uses** them: normal samples, correlation, a bivariate normal tail; it does not teach them). **Owned here:** loop design (which stages, how many interviewers, what each stage keeps) and **rubric calibration** (interviewer spread). **Research claims** are `ClaimLabel kind="research"`, hedged, **from memory**, no study named unless the author is certain. **No claim about any demographic group or about fairness of outcomes for groups; no real person, company or candidate.**
**The toy, stated up front (and on screen, in a persistent `Provenance toy` note).** Each candidate has a **latent skill** `s` drawn from `N(0, 1)` (seeded). An interviewer's **score** of a candidate is `s + e`, where `e = bias + noise` is zero-mean with variance `σ² = σ_b² + σ_q²` (`σ_b` the interviewer's leniency spread, `σ_q` question-to-question noise; invented constants). A **panel of k** interviewers averages `k` independent scores. **This shows the arithmetic of variance, not evidence that any rubric works:** a rubric is modelled as a **smaller `σ_b`, which is an input the learner sets, not something the toy discovered** (circular otherwise, and the page says so in those words).
**Spec.** Four scenes. Pool size `N = 1,000` candidates (seeded), `SeedField`.
- **Scene 1 · One panel, one decision.** A `Plot2D` scatter of 300 plotted candidates (the statistics use all 1,000): x = true skill, y = the panel's mean score, the **hire line** at the top `q%` of scores. Controls: **interviewers k** 1 to 9 (default 3), **noise σ per interview** 0.3 to 3.0 (default 1.2), **hire rate q** 5 to 50% (default 10%), **interviewers agree before scoring (correlation ρ between their errors)** 0 to 0.9 (default 0; a visible control that sets how much the interviewers' errors move together, e.g. after a group chat). Readouts: the correlation **r between score and true skill**, formula and measured; **recall** (of the candidates whose skill is in the true top `q%`, the share hired); **false hires** (hired but outside the true top `q%`). Formula: with error variance of the panel mean `σ² (1 + (k - 1) ρ) / k`, `r = 1 / sqrt(1 + σ² (1 + (k - 1) ρ) / k)`; the page also prints **effective independent interviewers** `k / (1 + (k - 1) ρ)`.
- **Scene 2 · Design the loop.** A funnel of **three stages** (resume screen, phone screen, onsite), each with `k`, `σ` and the **share it keeps** (defaults `(1, 2.0, 50%)`, `(1, 1.2, 40%)`, `(4, 1.2, 25%)`, so 5% are hired). For each stage the page shows the share still alive, the **recall of the true top 10%** after that stage, and the **mean true skill of those still alive**. A toggle **"no signal at the phone screen"** replaces that stage's score with **pure noise** (independent of skill). The point: where the loop loses the people it was built to find.
- **Scene 3 · Calibrate the interviewers.** Eight interviewers, each with a fixed **leniency** `b_i ~ N(0, σ_b²)` (seeded, `σ_b` default 1.0 invented), each interviewing 40 random candidates against the same hire bar (`bar = 1.0`, noise `σ_q = 0.7`). A bar chart of **each interviewer's mean score** shows the spread; a toggle **"anchored rubric"** sets `σ_b = 0.5` (**an invented input**) and the spread shrinks. A panel for **one candidate** (`s = 0.5`) shows the chance of passing the bar with a lenient interviewer (`b = +0.8`), a neutral one and a strict one (`b = -0.8`): `P = 1 - Φ((bar - s - b) / σ_q)`: **the same candidate gets very different outcomes depending on who they draw**.
- **Scene 4 · The debrief (`ScenarioStory`).** Invented: four interviewers, one strong "no", two lukewarm "yes", one enthusiastic "yes". Meters (invented): **regret** (expected cost of a wrong decision, k$; start 15, min 0, max 60, bad above 35), **days** to a decision (start 0, min 0, max 30, bad above 10), **goodwill** of the panel (start 7, min 0, max 10, bad below 3). Node table (every `because` begins "If ..."):

| node | choice | to | effects | because (pattern) |
|---|---|---|---|---|
| `h1` | `avg` decide by the average now | `E_hire_now` | regret +10 | If the scores are independent and the bar is clear, an average is a fair summary; with one strong dissent it hides the reason. |
| `h1` | `veto` let the strong no decide | `E_nohire_now` | regret +12, days +1, goodwill -2 | If the dissenter saw something the others did not, honouring it is cheap; if it was a mood, a good candidate is lost. |
| `h1` | `evidence` ask the dissenter for evidence against the rubric | `h2` | days +1, goodwill -3, regret -2 | If the concern is concrete, naming it settles the case; being questioned costs the dissenter some goodwill. |

**Model and oracles.**
- **Correlation:** closed form `r = 1 / sqrt(1 + σ² (1 + (k - 1) ρ) / k)` against the **measured Pearson r over 100,000 seeded candidates** within 3 standard errors (`SE ≈ (1 - r²) / sqrt(n)`), for a grid of `(k, σ, ρ)`; correlated errors generated as a shared component (`sqrt(ρ) * z_shared + sqrt(1 - ρ) * z_own`).
- **Recall and false hires (independent oracle):** the exact probability `P(S > q_z, X > q_z) / p` for a standard bivariate normal with correlation `r` (the tail of the true top `p` and of the score top `p`), computed by **numerical integration** (or Owen's T) in the test and checked against a **separate 2,000,000-draw Monte Carlo** with a different seed to within 0.005; extremes `r = 1` gives recall 1 and `r = 0` gives recall equal to `p`.
- **Funnel:** the hired share equals the product of the keep shares (`0.5 * 0.4 * 0.25 = 0.05`, exact by construction: each stage keeps its top share of those still alive); recall and mean skill per stage against a 200,000-candidate Monte Carlo (different seed), within 0.01.
- **Bias panel:** `P = 1 - Φ((bar - s - b) / σ_q)` against a 1,000,000-draw simulation within 3 standard errors.
**Test vectors (hand-worked; scipy confirmed the exact recall values).**
1. *Correlation.* `σ = 1`: `k = 1` gives `r = 1 / sqrt(2) = 0.7071`; `k = 4` gives `1 / sqrt(1.25) = 0.8944`; `k = 9` gives `1 / sqrt(1 + 1/9) = 0.9487`. **Quadrupling the panel equals halving the noise:** `σ = 2, k = 4` gives `1 / sqrt(1 + 4/4) = 0.7071`, the same as `σ = 1, k = 1`. `σ = 1.2, k = 3`: `1 / sqrt(1 + 1.44/3) = 1 / sqrt(1.48) = 0.8220`; `σ = 0.8, k = 3`: `1 / sqrt(1 + 0.64/3) = 0.9078`.
2. *Recall of the true top 10% (exact bivariate normal, hire 10%).* `r = 0.7071`: **0.4739**; `r = 0.8944`: **0.6802**; `r = 0.9487`: **0.7763**; `σ = 1.2, k = 3` (`r = 0.8220`): **0.5866**; `σ = 0.8, k = 3` (`r = 0.9078`): **0.7010**; `r = 0` (pure noise, from `r = 0.0173` at `σ = 100, k = 3`: **0.1054**) is the base rate 0.10. So **one interview at `σ = 1` finds fewer than half of the true top 10%**.
3. *Agreeing interviewers.* `k = 4`, `σ = 1`, `ρ = 0.5`: error variance of the panel mean `1 * (1 + 3 * 0.5) / 4 = 0.625`, `r = 1 / sqrt(1.625) = 0.7845` (against 0.8944 at `ρ = 0` and 0.7071 for one interview); effective independent interviewers `4 / 2.5 = 1.6`.
4. *Funnel (scratch, 200,000 candidates, seed 7, about ±0.003):* defaults: after stage 1 alive 50%, recall of the true top 10% **0.805**, mean skill 0.357; after stage 2 alive 20%, recall **0.641**, mean 0.915; after stage 3 alive 5%, recall **0.392**, mean **1.752**. 5. *Bias panel (bar 1.0, `s = 0.5`, `σ_q = 0.7`):* lenient `b = +0.8`: `z = (1 - 1.3) / 0.7 = -0.4286`, **66.6%**; neutral: `z = 0.7143`, **23.8%**; strict `b = -0.8`: `z = 1.8571`, **3.2%**.
